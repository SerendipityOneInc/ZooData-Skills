# WorkBuddy 组件验证

## Pre-build review

开发和 review 先读 [开发规范](DEVELOPMENT.md) 及受影响 Skill 的入口责任图。打包前核对全部修改来源和其使用方，分别检查：

| 层 | 必须检查 |
|---|---|
| Skill | 对象、输入、任务、方法、语义、报告内容一致；独立会话具备完整依赖 |
| Expert | 身份、领域、支持的业务问题、解题路径、判断条件、允许任务和实际装配一致；每类问题均能沿路径找到所需 Skill 任务，不用泛化提醒替代具体方法 |
| 公共模块 | 一条规则一个维护位置；用户沟通、业务交付、数据获取及专业方法各自只维护所属规则 |
| 装配与规范隔离 | 公共模块由 builder 统一装配；角色文件不导入 agent-core，开发规范和架构说明不写进业务 Prompt |
| MCP | 按实际连接工具选择和构参；完整 API/CLI 手册不进入运行包 |
| 报告与交付 | 证据支持、对象特征、缺失/零值、阅读顺序、语言和输出门一致 |
| 中文审阅 | 与英文运行文件对应，来源与版本可核对，不参与运行 |
| Prompt 可读性 | 条件、动作和指代明确；中英文语义完整，不使用省略式速记；来源摘要校验不能代替人工阅读 |

重点追踪：显式排序/默认排序/不支持排序，部分分页/空数据/调用失败，已有证据复用，独立 Skill 与多 Skill 专家组合，以及辅助能力是否改变了主问题。

### 会话用例

独立 Skill Session 和 Expert Session 分开验证，并使用自然用户问题。测试人员另外记录期望分析任务、必要证据和允许结论，不要求用户使用内部任务术语。完整用例保存在 .docs/workbuddy产品规划/skill规划 与 .docs/workbuddy产品规划/专家规划。

| 场景 | 预期结果 |
|---|---|
| 单独使用 Skill | 完成选定的数据分析及可读报告，不依赖专家指令 |
| 专家使用一个/多个 Skill | 只为当前已确认问题补齐证据，不扩大为其他任务，不重复中间报告 |
| 画像/趋势足以回答 | 使用上层指标；仅为具体疑问或明确明细请求下钻 |
| 常规关键词拓展 | 按相关性模糊召回，保留搜索量、ABA 排名及相关度 |
| 深入研究关键词 | 继续画像/趋势研究，不因词名或商品假设改成 ASIN 研究 |
| ASIN 与关键词关系 | 使用流量证据，不能靠语法/词义建立实际曝光关系 |
| 明细缺失与实际零值 | 处理、统计、展示和图表均保持区别 |
| 接口数据使用 | 成功返回值按定义使用，不要求卖家核实任何返回值；未知仅用于未取得的数据；矛盾由 Agent 检查口径并按任务补充佐证 |
| 用户选数字、自由提问或跳过 | 识别实际问题；不隐含换目的、不执行未选方向 |
| 同名对象对应不同市场 | 用已有上下文排除不匹配项，仍不明确时先选择；未确认前不批量查询候选市场 |
| 大结果与上下文成本 | 未指定数量时先取有限记录；复用已加载指令和工具定义；对文件中的大结果本地处理，不反复将整份原文加入上下文 |
| 能力不足或意图不明 | 按各专家自身的问题及证据条件答复，区分可补资料与无法判断；不推荐或转交其他专家；影响分析的歧义先澄清 |
| 混合语言和图表 | 周边表达跟随会话语言；图表按需且有清楚指标标识 |
| 首句和工具调用前的进度 | 采用用户问题的语言，不因英文指令或工具名切换语言，不播报加载专家或技能等技术准备 |
| 新对象首次出现在进度、正文或选项中 | 工具结果中的对象尚未对用户介绍时，先展示可读名称及必要标识，再使用简称或集合指代；不能直接用“两款套装”代替尚未介绍的两个商品 |
| 对象已在用户可见对话或当前消息前文中明确 | 简称能唯一对应既有对象时可直接沿用，不反复介绍；不能将工具结果或内部推理视为用户已知的前文 |
| 报告背景与有效条件 | 一行一项，只展示实际生效的筛选和必要背景；没有关键词时不传或展示关键词匹配选项，不照搬预设全部参数 |
| 必要筛选条件无法执行 | 仍按商品筛选方法说明尚未核验的必要条件及实际支持的筛选范围，不将其当作未使用的可选配置一并省略 |
| 新品榜筛选 | 默认按近180天上架筛选，用户指定的时间替代默认；不依赖长期保留的New Release标签，也不把带标签的老商品混入新品候选 |
| 只要求筛选候选或描述曝光 | 交付已取得的候选或曝光发现，不固定添加“未解决条件”章节，也不因缺少当前问题未要求的利润、供货、库存或合规资料而列出未知项清单 |
| 明确询问实际利润或可行性且必要资料缺失 | 只对用户所问而无法作出的判断简短说明，继续交付可支持的发现，不编造结论或将未回答的问题当作已解决 |
| 竞争对照只覆盖关键词前五条样本 | 在对应比较旁保留实际查询条件、排序和样本范围，结论限定于该样本，不扩展成全类目结论，也不追加无关未知项 |
| 多对象指标对比 | 每行或列只比较同一个指标；不同指标分行或分列，不省略后续对象的标签，不将参考指标当作综合等级 |
| 专家研究报告 | 生成一份可本地打开、离线可读的 HTML；按各专家提纲从总到分，主对话展示一张文件卡片；宿主要求末条文本时只作简短确认。无法展示卡片时交付一条报告链接 |
| 独立 Skill 报告 | 数据 Skill 默认在对话中展示结果。独立竞品工作流与竞品专家均按同一提纲生成一份 HTML。模拟文件已展示后检查最终回复：无重复链接、结论或口径说明；用户明确要求聊天摘要时才追加 |
| 报告交付结束 | 不主动附后续问题、编号探索菜单、选择卡片或选择新方向的邀请；用户自主提问后再分析 |
| 用户只要求商品筛选或表现比较 | 展示表现、差异和筛选匹配，不自动分成“继续研究、暂缓、对照”等决策组；用户明确要求决策时，才给对应建议及依据 |
| 必要输入确认 | 类目、模式或关键条件未明确时，分析前仍可使用必要的交互卡片；不把报告后菜单禁令当作禁止澄清 |
| 列表、分组或比较报告 | 当前目标所需内容从总到分；同一事实只选卡片、图、表、文字中的一种；不增加重复总览的章节，不以过程说明开篇 |
| 要求完整清单、历史序列或计算细节 | 按用户要求保留数量、基础指标和明细；精简说明不等于省略所需结果，未要求的历史佐证只展示影响本次判断的变化 |
| 用户明确要求下载或导出 | 按要求提供文件和下载链接；主窗口交付所请求的文件链接 |
| HTML 图片与图表 | 图片嵌入且限制尺寸；图表注明对象和单位，断点不连线；无远程依赖，桌面与窄窗口可读 |
| 选品类目统计 | 全量商品总数、样本量和类目覆盖分开；没有兼容汇总或完整数据时，不把样本类目数及排名写为整体 |
| 类目内 Top 商品 | 保持同一筛选条件及用户已确认的比较维度；同值保留并列，不用其他经营指标再判胜负 |
| 空数据、认证或额度失败 | 准确说明受影响范围，保留独立有效发现 |
| 用户提供后台报表/成本 | 仅在需要时应用商家资料规范，不从公共指标补造经营数据 |

## 单目标报告回归场景

| 场景 | 预期结果 |
|---|---|
| 新品榜未指定比较依据 | 先确认购买量、营收、增长或上架时间中的一种，再查询候选；不各取20条拼接 |
| 已明确按营收比较 | 直接沿用营收，不再默认按购买量取另一批；类目内筛选沿用相同依据 |
| 一个问题明确使用多项证据 | 只获取支持该问题所需证据，不将辅助指标展开成另一份分析 |
| 一次提出多个独立任务 | 先确认本轮处理哪个，其他任务不查询、不自动排队生成报告 |
| 图表已经展示一组数值 | 不自动附相同数据表或全文复述；标识、单位与必要解释仍保留 |
| 所有报告组件中的过程说明 | 用户未要求方法时，标题、正文、图、表、卡片及注释均不包含获取、处理、计算或校验过程；必要范围直接标注在对应结果旁 |
| 概览已展示数量或范围 | 正文不再设同内容的筛选概况；详情只有回答当前问题确实需要时才补充，不能只因字段尚未展示就增加卡片 |
| 图表已展示类目数量 | 类目名称、数量和必要覆盖范围放在图中；不另写倍数、计数过程或同一分布的文字复述 |
| 排序指标完全并列 | 在商品表旁简短标注一次共同值；不另设并列说明章节或重复总结，不增加无关特征来填充报告 |
| 多条独立分析发现 | 使用编号列表，每项一条发现；不将价格、评分、时间、配送等无关指标挤进同一段落 |
| 选品候选清单 | 不另加商品详情卡片；用户明确要求单个商品画像时再提供 |
| 多张卡片中只有前一张写出统计区域 | 补全每张卡片的统计对象及属性；百分比明确占什么整体，不用“同上”或相邻卡片解释 |
| 文案比较表使用“含”和“是／否” | 列名明确所检查的页面区域和短语出现情况；结果区分已出现、未出现及对应区域未取得，不展示内部字符串判断过程 |
| 页面没有出现完整短语，但商品已在该词下有曝光 | 分别保留文案与搜索表现的事实；不能只凭短语缺失认定搜索覆盖不足或必须补词 |

## 整稿结构审阅回归

报告内容组装后、HTML 生成前执行 reporting 的整稿审阅；独立 Markdown 报告在交付前执行。使用当前会话已有结果，不新增查询，不把审阅记录写入用户报告。

| 待审稿件 | 应有修正 |
|---|---|
| 只要求拓词分组，另有一节重复各组代表词和搜索量 | 删除重复章节，保留分类依据及带基础指标的分组词表；不为了补提纲取得画像或趋势 |
| 类目指标比较与逐类目画像重复相同需求和竞争数据 | 合并到对应比较，只有用户所问且尚未表达的差异才另作解读 |
| 标题声称解释需求结构，正文只有词数或代表词罗列 | 按实际回答的问题重命名；没有独立结果时删除，不将候选词构成当作市场需求结构 |
| 前文结论使用后文才介绍的对象或分组 | 先介绍必要对象和分组，将依据放到结论之前或旁边，调整顺序或合并章节 |
| 同一统计结果在不同章节被描述成不同覆盖范围或排序 | 依据现有结果统一名称、范围及排序说明，不修改来源数值，不追加查询过程 |
| 不同趋势窗口分别展示 | 各自保留准确期间标签；统一表述不代表把不同窗口改为同一期间 |
| 用户要求的最终选择已有独立业务判断 | 保留回答该问题的判断及必要依据，不因删重复总结而删掉用户所需答案 |

结构检查可验证规则装配、引用及执行次序；是否形成连贯报告仍需实际 Agent 会话验证。

## 业务判断与因果依据回归

这些场景检查 delivery 的业务判断门，与 reporting 的文档结构审阅分开；真实会话用例保存在 .docs/workbuddy产品规划/专家规划/测试用例/业务判断与因果依据.md。

| 证据与拟作判断 | 应有处理 |
|---|---|
| 数值上升，直接判断某种用词更重要 | 保留数值变化；没有当前目标或判断标准时，不补经营价值或词语作用结论 |
| 文案未出现完整短语，但商品已在该词下获得曝光 | 保留文字与曝光事实，不将词语缺失判为没有搜索覆盖，也不只凭缺失建议补词 |
| 标题缺少明确的每单件数，其他商品事实已说明件数 | 可认定购买数量信息在标题未说明，并提出补写件数；不承诺转化或排名提升 |
| 某泛词曝光占比最高 | 仅说明已有曝光来源，不能据此决定标题主次或主攻词 |
| 父体共用反馈涉及其他或未明确变体 | 保持父体反馈范围；不能直接认定当前子体存在该投诉问题 |
| 同一页面清楚列出多个变体的尺寸 | 不把不同变体的数值当作同一规格冲突；只判断对应关系是否清楚 |
| 前后表现变化，同时存在其他改动 | 报告变化与已发生改动；没有归因依据时，不认定某个单独改动造成效果 |
| 有支持目标改动归因的对照或测试记录 | 可在对象、期间和测试覆盖范围内作出相应效果判断，不外推未来收益 |
| 没有成立依据的诊断加上“可能”或“待验证” | 删除该诊断及仅靠它产生的建议；限定词不能替代事实依据 |
| 问题已有依据，经营效果还未测量 | 仍可给出直接回应问题的改进方案，经营收益不作承诺，不把缺少效果测试当作拒绝全部建议的理由 |
| 页面只存在词语重复或分隔符差异，关键商品信息已清楚 | 不仅凭这些文字特征认定存在运营问题；页面诊断须对应商品识别、购买判断或已有搜索表现证据 |
| 文案流畅但缺少明确购买数量等必要信息 | 按运营视角指出具体信息缺口及补充措施，不以文法流畅代替页面诊断 |
| 运营身份与各领域专业任务 | 各专家按自身范围分析；关键词独立研究不强制索要ASIN，市场或选品问题不因运营身份而自动增加广告、文案等任务 |
| 特征文本包含已知材质值及五条完整卖点 | 材质归入商品属性，后五条以“五点描述”按原顺序展示；保留所有信息，不将数组长度当作卖点数，不据此诊断第一条卖点缺少内容 |
| 完整卖点没有原文标签 | 仍按内容保留为卖点，不因没有方括号标题就当作属性或缺失内容；不补造原文标签 |

## 专家问题求解回归

从各专家真实入口验证自然业务问题；给定资料复演时明确禁止新查询。以下检查领域方法，不将模型重复规则文字视为通过。

| 问题及证据 | 应有处理 |
|---|---|
| 商品标题片段对应的相似搜索词排名不同 | 位置归属于 ASIN、搜索词及位置类型，不用它给标题片段评分；页面建议对应具体商品信息或购买问题 |
| 买家反映收到件数不足，页面已明确件数 | 区分履约体验与页面说明；不把再次改写件数当作解决缺件的依据 |
| 商品信息存在明确缺口，用户已提供必要规格 | 使用事实直接提出对应信息改进或起草文案，不因缺少经营效果测试而拒绝 |
| 只要求关键词拓展分组 | 使用相关度与返回基础指标完成词表，不默认查看商品构成、取得全部画像或为未指定商品分配词的用途 |
| 关键词画像包含多个需求、竞争和结构指标 | 分维度解释；不将广告覆盖率当费用或回报，不将头部商品均值当准入最低标准 |
| 关键词搜索量上涨，某修饰词同时出现 | 结论是完整搜索词的需求变化，不推断修饰词对买家的重要程度 |
| 市场商品数与销量变化方向不同 | 分别解释供给与需求；不以商品增加或某种价格带占比直接推出进入机会或利润 |
| 当前头部样本有新品销量 | 解释该样本的新品参与，不据此推算所有新品的成功率 |
| 候选在所选增长指标上并列 | 维持并列，不引入别的排序；只有明确询问持续性时才沿商品历史研究增长基数及序列 |
| 曝光变化但没有商家点击、购买和广告花费 | 研究曝光、位置及需求，不能由公开可见度判断转化损失或广告收益 |
| 评论人群数量不同且主题提及次数不同 | 比较相同主题、各自分母及使用条件；提及率不改写成故障率或退货率 |
| 竞品销量更高、页面用词不同 | 分别交付经营观测和内容差异，不将用词差异认定为销量差异原因；建议须回应具体产品或信息问题 |

各专家补充用例保存在 .docs/workbuddy产品规划/专家规划/测试用例；未执行的行为用例保持待执行。装配检查只证明专业方法已进入对应专家指令。

## 状态与实际集成

源码检查、ZIP、平台导入、本机安装、会话行为和正式发布是不同状态，分别记录。静态通过不证明 Agent 行为通过。

实际集成需检查 MCP 描述/Schema、工具映射、鉴权和读取能力；获得真实连接器 ID 后另验共享连接模式。真实调用和会话验证按当前用户授权执行。暂停会话测试时不得将未执行项目记为通过。


## 报告 Skill 装配与组件回归

1. 五个分析 Skill 不包含 HTML 生成脚本或模板。报告工具可独立验包，与各专家内置副本同源；各专家预加载主分析 Skill 和报告 Skill，允许的数据分析任务保持原范围。
2. 报告 Skill 的入口、组件、示例、脚本和模板在二级目录内形成完整依赖。用解包后的脚本和示例实际生成文件，不能只检查链接文字。
3. 固定页首只出现一次，背景逐项分行；完全重复的内容块应在写文件前报错。相同数值属于不同对象时应正常展示。
4. 表格、图表、编号列表、零值与缺失、图片嵌入、文本转义、模板占位符及桌面/窄窗口版式均检查。编号列表须使用独立列表项，空项和非文字项应报错。脚本不承担近义复述判断；整份报告仍按 reporting 的内容检查执行。
5. 记录源码检查、原生装配校验与真实会话结果；静态检查不代表 Agent 已按需调用报告 Skill。
6. 报告 Skill 的整稿审阅链接须定位到实际打包的 reporting 章节，且位于生成命令之前。检查引用片段有效，不仅检查文件存在。

## 竞品业务流程试点

1. 分别检查独立竞品对比 Skill 和竞品专家内的同名副本。从流程引用逐项核对数据 Skill、各自的主接口及兜底依赖。检查独立包内的全部链接均可达，且没有装入旧的通用方法目录。
2. 用指定 ASIN 的价格走势、标准竞品对比、结合自家产品的差异化三类问题检查路由。价格走势仅使用相关历史和必要的规格，标准比较使用维度 1–4，差异化任务围绕商品事实和同主题反馈。经营建议由专家结合用户目标提出。
3. 独立竞品工作流与专家均应生成 HTML；用同一份报告数据验证两者展示一致。原生包结构校验和实际会话验收分别记录。

## 选品工作流验收

1. 专家和独立工作流使用相同的三个示例。增长市场按同层级类目整体销量环比比较；爆款按商品购买量排序；新品市场比较各类目畅销商品中的新品数量。
2. 对示例之外的自然语言提问，复用明确的目标、范围和排序，只澄清影响分析的缺项。明确筛选时只生成一次对应条件与排序的请求。
3. 比较同值、缺失与零值，按取得的样本标注类目分布。零命中时仅交付范围与结果。
4. 对同一份候选数据，独立流程和专家内置报告工具应生成相同 HTML。实际界面中的点击、取数、文件展示单独验收。
