# 组织所选任务的对比结果

| 任务 | 内容顺序 |
|---|---|
| 分析单个竞品 | 点明商品，依次呈现卖点、售价、近期购买量、主要流量来源和买家反复提到的优点与问题。 |
| 最近三个完整月的购买量 | 用一张表对比购买量。商品ASIN 和父体分相邻两行，每列一个自然月的购买量下限（件），缺失直接写在对应单元格。摘要卡片留空。 |
| 竞品变化监控 | 标明 ASIN 和实际观测期间，按日期列出变化项、变更前和变更后。对于未观察到变化或缺少可比记录的项目，各用一句话说明。 |
| 查找可比商品 | 交代目标商品和筛选依据，在同一份清单中展示候选名称、ASIN 及纳入理由。 |
| 对比竞品 | 点明比较对象和主要差异，依次呈现当前经营表现、流量来源和历史变化。深度研究增加同主题买家反馈对比。 |
| 比较指定方面 | 回答用户的问题，再展示支撑判断的可比数据。研究趋势时标明期间并展示走势。 |
| 分析商品差异化依据 | 从买家需求或使用场景入手，把商品或页面差异与相关买家反馈放在一起，标明各项发现对应的商品。 |

监控任务取得日级历史响应文件后，运行[变更汇总](../../../../skill/workflows/competitor-comparison/summarize_changes.py)，依次传入 `response.json ASIN startDate endDate` 和用户所问的字段（`title`、`imageUrl`、`price`）。直接用输出的日期、前后值和各字段覆盖范围填写监控表。原始响应包含 `data.asin`，并在 `data.context` 中提供 `granularity=day`、`requestedDateFrom`、`requestedDateTo`。对于用户提供的片段，直接比较其中带日期的记录。标题和主图可以用期间开始前最后一个已知值作基准，只展示期间内观察到的变更。变更次数为 null 表示可用记录不足以比较。

1. 把影响比较的规格放在对应指标旁。仅保留本次涉及的章节；缺少指标影响判断时，指出具体哪部分尚无法回答。
2. 综合竞品对比以“各款商品的优劣对比”收尾。用一个 `profiles` 内容块并排展示，每款商品一张卡，标明商品名和 ASIN。分列相对优势与劣势，每项用一句话给出决定判断的对比证据；证据只支持一面时，只写这一面。专项对比和单品拆解在最后一项相关发现处收尾。

生成 HTML 时，在报告 JSON 顶层填写本次任务 `task`。按上表顺序，取值依次为 `teardown`、`monthly-purchases`、`monitoring`、`discovery`、`comparison`、`focused-comparison`、`differentiation`。

## 单品拆解的首屏与正文

1. 标题和范围先标明商品、ASIN 与站点。首屏用两至四张结论卡回答本次最重要的问题，每张卡以业务主题为标签、以简短判断为主文，再用一句话给出关键证据及其期间。指标的观察范围就近说明。
2. 正文标题写明各节发现。价格章节使用一个 `daily-history` 块，指定 `field="price"`、当前商品 ASIN 及用户要求的价格观察期间。`source` 指向直接保存的 products/history 原始 JSON 响应，生成器逐日配对价格并统计变价次数。日期与价格条数不一致时重新读取原始响应。确实无法取得日价时，在本节说明缺项。月购买量另图展示，标明实际覆盖月份。当前款式和整个 Listing（含该款式在内的所有变体）按相同月份绘图。缺月留空，不同父 ASIN 分线展示。没有 Listing 汇总值时，绘制当前款式已有的记录，并注明父体合计未获取。仅有一个价格时列出日期与价格。
3. 当页面卖点和买家反馈涉及同一具体属性时，将两者放在一起解释。分别标明评论中的认可与问题、各自样本；同一评论可能涉及多个主题。只引用已取得的原文。每节用新的证据展开首屏判断。
4. 单看一项走势容易误判时，在对应图表旁使用正文结论卡（`callout`）。卡片标题写业务判断，用一两句话指出哪项对比支持它；判断只适用于某个款式或期间时，就近写明。用卡片替换原解读段落，章节标题只标明分析主题。
