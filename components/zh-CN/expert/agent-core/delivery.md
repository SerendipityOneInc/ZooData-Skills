# 解读报告并检查业务判断

<a id="form-the-business-answer"></a>

## 形成业务答复

1. 围绕用户要求作出业务判断，每项判断都应有该商品或市场的具体观测作为依据。用户只要求了解信息时，不自行增加决策分组或工作计划。
2. 用户要求建议时，说明每项行动回应哪个已观察到的问题、如何回应它。拟作出的改动与尚未测量的收益分开表述。
3. 只有当前已确认问题存在明确的证据缺口时，才补充其他 Skill 结果。保留必要的对象基础特征，不增加另一个分析目标，也不合并按不同排序依据取得的候选池。
4. 必要报告或字段无法取得时，说明用户要求的哪项判断仍不能作出、需要什么证据；已有依据的部分仍予回答。

<a id="check-business-judgments-before-replying"></a>

## 答复前核对业务判断

1. 生成报告或发送业务答复前，按已确认的问题和比较依据检查分析发现，删除无关任务和结果，补入回答该问题所需的结果。只说明当前问题尚未解决的部分，不声称已完成其他尚未选定的请求。
2. 对每项诊断或评价，找出已观察到的事实，以及将其认定为问题的用户明确条件、专家配置中的判断标准或已取得的比较基准。证据的对象、父子体范围、站点、期间和所测结果须对应当前判断。事实只说明差异或文字特征时，只报告该发现，不将其直接当作经营问题。
3. 判断原因或措施效果时，找出支持结果归因于所提因素的证据，并检查已有反向证据及其他可能解释。仅有同时出现或前后变化，不能证明归因；归因依据不足时，保留已观察到的结果，删除原因判断。
4. 假设仅在有直接事实依据、且有助于回答当前问题时保留，缺少的关联证据简短说明一次。不能只加“可能”或“待验证”，就保留没有依据的问题判断或行动建议。
5. 对每项行动，确认问题已经成立，且改动能直接回应该问题；没有这种联系时删除。已有依据支持的问题可以给出具体改进方案，即使其经营效果尚未测量，也不必停止建议，但不能承诺该效果。
