# 报告呈现规则

本规则覆盖报告及所有面向用户的文字，包括进度说明和必要的需求澄清。

<a id="choose-the-delivery-format"></a>

## 选择交付格式

1. 专家报告和自带 HTML 报告提纲的独立工作流，均按任务提纲交付一份 HTML 文件。
2. 独立使用数据 Skill 时默认在对话中以 Markdown 交付所选任务的数据报告，用户指定其他格式时按其要求。专家会话中的 Skill 中间结果用于最终报告，不为每项任务单独生成文件。
3. 必要输入问题、进度说明和简短事实回答保留在对话中。交付后用户提出新的分析问题时，复用适用证据生成聚焦该问题的报告。用户明确要求其他格式时按其要求。

<a id="hand-off-the-html-report"></a>

## 交付 HTML 文件后结束本轮

1. 完成的 HTML 只展示一次。使用 WorkBuddy 的 `present_files` 时，只提交最终 HTML 文件，展示说明填写报告标题。
2. 宿主确认文件已展示，即由文件卡片完成交付，结束本轮。若宿主必须接收末条文本，仅用当前对话语言简短确认，例如“报告已生成。”
3. 无法展示文件或展示失败时，发送一个以报告标题命名、可打开的链接。结论、数字和口径说明均写在 HTML 内。仅当用户明确要求在聊天中另附摘要或附件时才追加；要求在报告中归纳结论时只交付报告。

<a id="organize-the-answer"></a>

## 组织正文

1. 研究报告从整体范围展开到分组、重点对象和有依据的结论。范围和关键数量放在顶部，正文从实质分析开始。只选用回答当前已确认问题所需的提纲内容，提纲不代表必须依次完成全部章节。不重复总览，也不为填满提纲获取无关数据。
2. 每个问题选一种最易读的方式呈现。图或表已能回答问题时，本节到此结束。单位、期间及必要的统计范围写在标题、坐标轴、表头或图例中。只有用户的问题仍有一部分需要解释，且已有证据支持时，才补充业务解读。
3. 面向普通业务用户，直接说明正在分析什么、要做什么或发现了什么。使用熟悉且前后一致的业务名称，不自造简称，也不用比喻或含糊的近义词替代。删除不影响理解的铺垫和修饰。整份报告只展示结果及必要的解读；用户明确要求时，才说明数据获取、处理、计算或校验过程。此规则适用于所有报告组件。
4. 将抽象指标名称改写为实际衡量或比较的内容。接口返回的分级和类目名称使用当前对话语言。指标标签保留准确含义、统计范围和单位。只解释理解结果所必需的缩写或分级。
5. 独立发现使用编号列表，每项单独展示一条发现，用一至两句短句说明。不将无关指标挤进一个段落；多个对象共有的指标使用表格展示。
6. 历史佐证概括为影响当前回答的变化，保留理解该变化所需的期间和数值。只有用户要求时，才展示完整序列和逐字段说明。

7. 已回答本次问题时，结束报告。

<a id="present-objects-and-data"></a>

## 展示对象与数据

1. 对象列表优先使用表格，相同指标保持同列。每个对象独立成行，包含可读名称、识别或操作该对象所需的标识及任务基础指标。技术编码留在内部，用户要求时再展示。其他指标只在回答当前问题需要时加入；用户只要名称时按其要求交付。 商品清单、候选和代表商品统一使用父体或子体模板。每个商品的基础信息只展示一次，后续图表用 ASIN 标识即可。
2. 将展示数值、指标名称、单位及汇总与来源记录核对。每个对比指标独立成行或成列，各对象的含义和单位保持一致。将挤在同一单元格中的不同指标拆开，不能靠其他对象单元格的说明猜测本格数值的含义。
3. 单位标在对应数值、列名或图轴旁。在指标旁注明来源返回的实际数据日期或统计期间。请求期间与实际期间不同时分开标明。缺少实际日期时只写已知期间，不用请求时间代填。仅在影响理解时补充分母或样本范围。删除未对应当前指标或重复已有标注的独立口径说明。
4. 实际零值写为 0，缺失写为“未获取”或“暂无数据”，不共用空白或破折号；评分数和文字评论数分开标注。
5. 共用的样本范围在页首“数据口径”说明一次。采用前 N 名时，写明按什么排名、取多少款；个别组不足 N 款，在同处注明即可。只有用户要求比较样本量，或解读数值确实需要逐行看分母时，才列样本数。其他覆盖差异在受影响的结果旁标注。只有口径相同的汇总或完整数据覆盖才能支持整体数量和排名；否则标为样本结果，不将单页结果推成整体。
6. 报告背景使用带标签的条目，一行一条信息。只保留理解结果所需的已确认范围、有效筛选条件、期间、排序或覆盖范围。有效条件取自实际查询和本地筛选，不照搬预设中的全部选项。依赖输入缺失的选项、未使用配置及技术处理细节不展示。
7. 过宽或过密的表格拆分，保持相同对象顺序和业务标识。用户要求的信息无法放入简洁比较表时，在相关分析旁补充，不重复表内数值。
8. 当前问题需要比较表以外的对象详情时，才使用详情卡片；只加入回答该问题必需的事实，不能因为某个字段尚未展示就增加卡片。商品图片有助于识别这些对象时再加入。缩略图限制尺寸并保持比例，商品模板以“暂无图片”标示缺图。
9. 每张关键指标卡片都须能独立读懂：写明统计对象、具体属性和指标，必要的样本范围或百分比分母放在本卡片内。不依赖另一张卡片或“同上”解释数值。表头写清检查什么，单元格明确描述已观察到的结果，不用含义不明的“是／否”。

10. 报告和对话只说明业务期间及指标含义。快照、分区和取数机制留在内部。完整月份直接写年月，需要区分频率时才写“月度数据”。比较期间和趋势区间写到年月；日度观测和未结月数据保留实际日期。月末记录的近 30 天销量称为“月销量”，注明所属月份和单位。下限值用“至少”或“+”表示，估算值和均值分别标明“预估”和“平均”。
11. 仅使用 ZooData 亚马逊美国站数据时，来源统一写“数据来源：ZooData 亚马逊美国站数据”。英文写“Source: ZooData Amazon US data”。混合来源按实际使用情况列出。报告开头的“数据口径”写明共同统计期间。已有说明时直接沿用；仅在某项数据期间不同时单独标注。单位和下限标记仍随数值展示。

<a id="show-product-purchase-volume"></a>

## 商品购买量

1. 同时展示商品ASIN 和父 ASIN 全部变体合计，两组使用相同指标和期间。专项分期比较表的左侧用商品名和商品ASIN 作跨行表头，右侧分“本商品”和“父体合计”两行。趋势图沿用这两个图例名称。商品展示使用共享商品模板。子体列出商品 ASIN 和父体 ASIN；只有父体时标为“父体商品”，显示父体 ASIN 和父体销量。父体合计已含本商品，汇总多个商品时同一父体只计一次。
2. 各组分别与自身基期比较，排序沿用用户选定的指标和范围。缺值写“未获取”，零值保留为 0。跨期发生父体变更时分开展示。
3. 按数据 Skill 提供的口径标注购买量。非月末的滚动记录写“近 30 天购买量下限（件）”，有实际截止日时一并列出。尚未定稿的记录标明其所属月份和已知截止日。只有相邻两个完整月的比较才写“月环比”。

<a id="present-rates-and-their-bases"></a>

## 增长率和比较基准

1. 筛选条件、表格、图表、卡片和正文中的增长率统一用百分比。按来源单位换算一次：小数 0.1 显示为 10%，159.0 显示为 15,900%；已是百分数的值直接加 %。降幅保留方向，真实零值显示为 0%。其他比例指标同样写清百分比及其分母；两个占比相减用“百分点”。
2. 写明“哪个对象的哪项指标，相对哪个对象或哪个期间的同口径指标”。多个商品各自与历史比较时，表头可共用“各商品……较……”，每行保留商品标识。独立卡片或结论句应能单独读懂。展示实际增长率时，将同口径的基期值、本期值和增长率放在同一行或同一张卡片，注明单位。优先使用原始观测值；仅当指标公式和来源精度能唯一确定缺项时才补算，并标注“推算”。其余缺项写“未获取”。筛选门槛只列比较基准和百分比。
3. 比较期未知时明确标注“比较基准未提供”；基数为零时相对增长率不可计算。仅在来源提供或允许按同口径数据计算时展示增长率，保留缺失值。

<a id="describe-a-share-of-a-total"></a>

## 如何描述占比

1. 进度播报和报告都写清哪一项占什么总量的百分之几。多项合计时点明所含项目。只有统计对象、指标、期间和分母相同，且各项互不重叠时，才相加占比。有重叠时，使用去重后的合计数计算占比。
2. 仅对同一整体的构成占比使用以下称谓。按舍入前的数值分档。0% 至低于 40% 称“占少数”；达到 40% 但低于 60% 称“与其余部分大致持平”；达到 60% 至 100% 称“以……为主”。显示百分比时保留足够的小数位，使读者看到的数字与分档一致。
3. 无法确定占比时，只报已知数值。只知道排名时，只说明相对顺序。增长率、转化率和跨期变化沿用各自指标的口径。

<a id="use-charts-and-files"></a>

## 使用图表与文件

1. 图表比文字或窄表更直观时才使用。变化用折线图，对比用柱状图；饼图只用于已知整体中互斥的组成项。单位不同或量级差异明显的时间序列，使用上下排列的小图，时间标注对齐，各图单独标明数值轴和单位；不用其他图型或双轴。
2. 图中对象用业务标识识别，序列、颜色和缩写有可见说明，不依赖悬停。排名指标注明数字越小越靠前；图表行号不当作数据排名。
3. 绘图使用来源数值，缺失点保留缺口；商品素材只使用接口返回或用户提供的资源。
4. HTML 报告组合短文字、紧凑表格和有助于理解的图表。版式适应窗口宽度，字号易读，标题清楚，并有打印样式。不使用脚本、外部字体或 CDN。嵌入 PNG/JPEG 图片数据和 SVG 图表，使文件离线可读。
5. 生成文件使用宿主支持的文件链接交付。独立 Markdown 报告在支持时使用内嵌图表，否则改用窄表或简短文字。

<a id="remove-inappropriate-prompts-and-caveats"></a>

## 删除不当提示与附加说明

1. 删除任何要求卖家核实 ZooData 返回数据，或标为“待卖家确认”的提示。已取得的值照实展示，未知只用于未取得的信息。
2. 仅当信息缺失或数据矛盾导致用户明确询问的问题无法回答，或影响已交付发现的解读时，才在对应发现旁简短说明一次。省略与当前问题无关的未知项、泛化免责声明，不默认设置“未解决条件”章节。

<a id="check-each-message-before-sending"></a>

## 发送前检查每条消息

1. 发送任何可见消息前，包括首条进度说明，按会话的对话语言及上述用语规则检查说明文字。专家会话沿用预加载“对外表达与进度说明”已确定的语言；独立 Skill 会话使用宿主的对话语言。关键词、品牌和业务标识保留原文，用户指定的其他语言只用于对应成品；发现不符合项时，改正后再发送。专家每次发进度前（包括两次工具调用之间），按“对外表达与进度说明”检查草稿，删去内部操作和已说过的计划。删完无内容就跳过这条消息。
2. 发送任何消息前，检查每个简称或集合指代，确认它能唯一对应到用户可见对话或当前消息前文已介绍的对象。工具结果和内部推理不算已经向用户介绍对象。指代不清时，先用可读名称及必要的区分标识介绍对象，再使用该指代。已有上下文足够明确时，沿用既有名称。

<a id="review-the-complete-report"></a>

## 交付前审阅整份报告

1. 全部内容起草完成后，生成或交付前，将标题、范围及所有章节作为一份完整报告审阅。逐节确认其回答的具体问题，删除没有独立回答作用的章节。标题应准确表明该节回答的问题、所作比较或主要发现，不用正文没有提供的结果作标题。
2. 按最终展示顺序通读。对象、分组和必要指标含义应先介绍，再用于解读。支撑结论的数据应在结论之前或旁边。前文必须依靠后文才能理解时，调整顺序或合并章节；同一结果的前后描述冲突时，统一修正。
3. 修正指标名称错配、数值含义不明、整体与样本混淆及对比单元格混用不同指标的问题。逐项核对比较指标、样本、期间和排名依据是否与用户的问题一致。删除用户未要求且不影响作答的期间，不用其他期间的数值给并列项再排名。用户要求跨期间对照时，将所比较的期间放在同一张图或表里，包含主期间。删除未生效的筛选条件。逐处按“增长率和比较基准”核对百分号和比较双方。
4. 先单独读图及其标题、坐标轴和图例，再看周围的卡片、表格和文字。删除已展示的数值、对图中走势的复述，以及重复同一组数据的表格。表格还承担其他必要比较时，把读懂该比较所需的指标放在一起，删除与其重叠的展示。用户明确要求逐项明细时保留明细表。
5. 交付前修正稿件中的上述问题；HTML 内容改变后重新生成文件。确认实际文件存在，图表和图片已嵌入。审阅在内部完成，不将审阅记录加入报告，不为审阅新增数据查询。
