# MCP 数据获取规范

<a id="select-tools-and-construct-requests"></a>

## 选择工具并构造请求

1. 只使用 Skill 声明范围内已连接的只读 MCP 工具。能力表中的读取路径用于匹配工具，实际调用名称从已连接工具中确定。
2. 首次使用工具前，读取当前描述和 Schema；同一会话内复用该定义，只有工具变化或错误要求重新检查时才再次加载。按支持的字段、类型及默认值构造日期、站点、批量、筛选和分页参数。
3. 领域说明与当前接口定义不同时，按接口定义解释字段。必要定义未提供时，保留已返回值，不猜测依赖该定义的结论。
4. 执行依赖对象选择的数据查询前，确认每个对象都在用户明确指定的范围内，或已由上下文唯一确定。匹配后仍有多个可能对象时，先确认目标再查询其数据；匹配列表不是用户已选择的比较对象集合。

<a id="choose-the-appropriate-evidence-level"></a>

## 选择证据层级

1. 分析优先使用所选任务的画像、趋势指标及支撑观测；其中已包含当前问题所需指标时，不为重算相同指标而查询明细。
2. 上层指标留下具体未解问题，或用户明确要求记录、字段、原始序列时，查询对应明细。
3. 没有对应上层指标时，使用该任务规定的主要来源。

<a id="select-the-trend-period"></a>

## 确定趋势查询期间

1. 用户已指定期间、截止日或粒度时沿用其要求。未指定时长时，月度趋势查最近 6 个月，周度趋势查最近 3 个月，日度趋势查最近 1 个月。默认使用截至指定日期或最新已完整观测的周期；用户要求包含本期时纳入未结束周期。
2. 接口默认窗口不同时，显式传入起止日期或窗口。周度和日度序列按对应的日历月数回溯。接口只支持固定窗口时选最接近的受支持窗口，并按实际长度标注。数据覆盖或额度有限时注明实际取得的期间。该规则只用于趋势查询。

<a id="apply-sorting-and-pagination"></a>

## 处理排序与分页

1. 按用户指定顺序或领域方法的默认顺序，选择工具支持的排序字段和方向。领域默认顺序也属于排序要求，除非接口明确的默认排序完全相同，否则显式传入排序参数。用户和领域方法都没有排序要求时，省略参数，使用接口明确的默认排序；接口未说明默认值时，将顺序标为未指定。
2. 同一次查询的各页保持对象、期间、筛选和排序参数一致。
3. 用户未指定数量或完整覆盖范围时，列表查询首次以 20 条为默认，工具支持时使用；只有当前问题需要更多覆盖时才继续。用户明确的范围和工具约束优先，不把初始一页描述为完整覆盖。

<a id="reuse-responses-and-record-usage"></a>

## 复用结果与记录用量

1. 新查询前，已有响应符合本次对象、站点、期间、筛选和指标口径要求时，直接复用，只查询仍缺少的数据。
2. 每次查询遵守用户的覆盖范围和费用限制；限制导致必要查询无法继续时，停止该查询，说明尚未取得的数据。
3. 检查完整结构化响应，包括预览未显示的记录。大结果已有文件时，在本地处理全部相关记录，只将当前问题需要的字段、汇总或选定记录加入分析上下文；保留原文件和标识供后续读取，不再次打印整份 JSON。保留来源工具、请求条件、实际排序、原始行序、批量对象标识及状态，以及返回的用量。
4. 宿主拒绝读取已保存的结果时，尊重权限限制，优先使用同一次查询仍可读取的结构化结果。资料不完整时，交付有依据的部分，并指出哪项业务结果暂缺。自行处理分批和结果读取，不让用户选技术方案或开放内部目录，也不为缩小响应而重跑成功的付费查询。
5. 一次涉及较多对象且尚未约定预算时，按接口的计费单位和剩余对象数或请求数估算积分，取数前一次确认研究范围和预计消耗。已同意的预算内直接执行。确需确认预算但无法可靠估算时，可请用户设定积分上限，仅在能够遵守上限时执行。
6. 用量只按返回元数据记录，不补写缺失值，不将总量与其组成项重复累计。

<a id="handle-authentication-and-private-inputs"></a>

## 处理鉴权与私有资料

1. 通过连接器授权流程配置凭据，不在普通对话中索取，也不将凭据放入查询参数、消息或输出文件。
2. 只发送接口规定的查询输入。商家成本和私有报表留在分析上下文；只有所选工具确需且用户已授权传递时，才发送这些资料。

<a id="handle-failed-or-empty-results"></a>

## 处理失败与空结果

1. 所需工具或连接不可用、凭据被拒绝或额度耗尽时，停止受影响的查询，说明原因。
2. 参数错误仅按返回提示和当前 Schema 修正；无法据此确定修正内容时，停止查询并说明缺少的请求信息。
3. 限流或临时失败只按连接器明确的重试规则处理，并遵守宿主及费用上限；没有明确规则或达到上限时停止，不重跑成功页。
4. 正常空结果表示当前查询条件下没有匹配记录，不作为错误重试。
5. 某次查询失败后，继续不依赖该结果的必要查询，保留成功结果并说明未完成部分。
